# 招聘信息采集（考公 / 考编 / 央国企）

## Context

用户在追踪**体制内 + 央国企**的招聘窗口，需要一个每天更新的「当前在招聘单位」清单，且清单里每个「招聘中」单位都要有本地岗位表文件；拿不到的要如实标注原因，不能空着也不能编。

本 skill 只负责**采集**：找到公告、判定是否在招、把岗位表下到本地、写成 JSON 分片。
把分片变成清单是另一个 skill（`zhaopin-list-build`）的事，不要在这里手改台账或清单。

## 铁律

1. **不许编。**日期、人数、URL、文件名，只能来自本轮实际抓到的页面。抓不到就写 `待确认` 或留空，并在 `备注` 写清试过哪个入口、返回什么。
2. **不许启动浏览器。**沙箱禁止命名管道，headless Chrome 必崩。只用 `python requests`。
3. **中文一律写文件。**控制台是 GBK，`print` 中文会乱码。结果写 UTF-8 JSON，再用 read 工具看。
4. **岗位表 >10KB 才算数。**下完后 `ls -l` 验证，小于 10KB 一律删除并记失败——那是错误页不是表。
5. **既有条目必须原样带上。**每轮覆盖写分片时，上一轮的条目要全部保留（含 `单位`/`项目` 原文，不许改名），只更新状态与备注。改名会产生重复行。

## 步骤

### 1. 查板（如本机有任务看板）

```
taskboard_list(status="todo", workspaceId="<工作区路径>")
```
有可认领任务先认领再干活；没有就继续。**看板不是必选项**，没有这个工具就跳过。

### 2. 并发派 4 个分片 agent

一次性发 4 个 subagent，每个的 prompt 必须写清：

- 今天的日期与当前时刻
- 状态口径：`招聘中`（报名窗口含今天）/ `已结束` / `未开始` / `待确认`
- 只用 python requests，Chrome 不可用
- 结果覆盖写 `数据/raw_<块>.json`，**必须包含该块全部既有条目**
- 岗位表下到 `岗位列表/<类别>/`，命名 `<单位>_<项目>_岗位表.<ext>`，路径要带类别子目录
- 下完 `ls -l` 验 >10KB，失败写原因
- `单位` / `项目` 字段一字不改
- 明确告知：**工作区还有别的分库（外企、雄安）**，不要读写 `raw_外企.json`、`raw_雄安_*.json`

| 分片 | 文件 | 覆盖 |
| --- | --- | --- |
| 考公 | `raw_考公.json` | 国考、31 省省考、定向选调、选调生 |
| 考编 | `raw_考编.json` | 事业单位统考、教师编、医疗卫生编、三支一扶；含雄安新区 |
| 能源军工 | `raw_能源军工.json` | 电网、五大发电、三桶油、中煤、中化、烟草、中核、航天、航空、航发、船舶、兵器、电科、中电 |
| 建筑通信金融 | `raw_建筑通信金融.json` | 中建/中铁/铁建/交建/中冶/电建/能建/中车、移动/联通/电信/铁塔、国铁/邮政/中远海运/招商局/华润/中粮/宝武/五矿、六大行 + 政策性银行 |

详细职责边界、去重规则见 `references/split-rules.md`；字段定义见 `references/schema.md`。

### 3. 每轮必做的两个"雷达"

这两件事不加就会漏，而且是整类地漏：

**A. 省考雷达（考公分片必做）**
抓一次聚合汇总页（中公《20XX 各省公务员考试公告汇总》或华图同款），把"已发公告的省份"和台账已有省份做**差集**。
差集非空 → 立即补收该省条目 + 下载职位表。

> 教训：只盯"名单里的省"时，天津 2027 市考（1,515 人）发布后整轮漏收；北京 2027 市考也是靠雷达才抓到的。

**B. 雄安监测（考编分片必做）**
新区不属于任何省考序列，单独盯三处：
`www.xiongan.gov.cn/tzgg.html`、`chinaxiongan.cn` 招聘公告栏、新区公共服务局。
注意公共服务局的 xiongan.gov.cn 子栏目经常 404，招聘实际发在新区官网通知公告里。

### 4. 国考专项

```bash
python 脚本/gk_probe.py      # 写 数据/gk_others.json
```
在返回的 `resList` 里找「招考简章」的 `resResourceId`：

```bash
python 脚本/dl.py get --url "http://dl.scs.gov.cn/download/<id>" \
  --out "岗位列表/临时" --name "国考20XX_招考简章.zip"
```
zip 内是 `招考简章.xls`（职位表）。`ZipFile` 必须 `with` 关闭，否则 Windows 删不掉临时文件。
页面上的"点击下载"有图形验证码，走 `dl.scs.gov.cn/download/{id}` 资源接口可绕过。

> 该接口会阶段性返回 `{"exam":"error"}`（通常是瞬时），遇到先重试一次，仍失败就改用 `www.scs.gov.cn` 专题页。

### 5. 补缺

对每个 `状态=招聘中` 且 `下载状态 != 已下载` 的条目：

```bash
python 脚本/dl.py links --url "<公告页>" --kw "附件,岗位,职位,计划,xls,pdf" --save 数据/_links.json
```

- 有附件 → `dl.py get`
- 纯在线岗位库（国聘/北森/智联/中公报名系统这类 JS 单页）→ 存岗位查询页 HTML：
  `--name "<单位>_岗位查询页.html"`
- 都拿不到 → `下载状态` 记 `未找到附件`（无附件可下）或 `失败`（有附件但抓取失败），`备注` 写明 403 / 412 / TLS / DNS / SPA 空壳

这两者要区分：`失败` 是"本该有但没拿到"，`未找到附件` 是"对方就没发文件"。

### 6. 收尾

采集只产出 `数据/raw_*.json` 和 `岗位列表/` 下的文件。**不要手改** `数据/units.json` 和清单 `md`——那是 `zhaopin-list-build` 的活。

## 分片失败怎么办

某个分片 agent 挂了（无产出 / 报错）：

1. **先看它还缺什么**——如果只差两三处（比如"确认某入口开了""翻转一条状态"），派一个小任务**只补缺口**，明确写"不要重扫、不要重下已有表"。
2. 缺得多的，才重跑该分片全量。
3. 重跑前确认 `数据/raw_<块>.json` 还是上一版，别让它读到别的分片半成品。

> 实测：一次只补缺口的重跑约 15 分钟、新增 0 条；全量重跑要 25 分钟以上。

## 环境坑（详见 references/sources.md）

| 现象 | 处理 |
| --- | --- |
| `EXECUTOR_UNAVAILABLE`（CreateFileMapping） | 换 `pwsh` 重跑，不是权限问题；并发 bash 时高发 |
| `curl` 报 `SEC_E_NO_CREDENTIALS` | 用 python requests，别修 curl |
| 控制台中文乱码 | 写 UTF-8 文件再 read，不要 `print` |
| 银行/运营商站 TLS 握手失败 | `ssl.OP_LEGACY_SERVER_CONNECT` 或改用官方转载页 |
| 站点 412 / 403 / 405 | 瑞数/云 WAF，别死磕，换聚合站或高校就业网 |

## 汇报

3~8 行中文：在招数、新增几家、今天/3 天内截止、岗位表成功与失败数。
不要粘整张表。
