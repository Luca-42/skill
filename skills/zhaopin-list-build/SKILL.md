# 招聘清单生成与校验

## Context

采集阶段只产出 `数据/raw_*.json` 分片和下载下来的岗位表文件。
本 skill 把分片合并成**可读清单** `当前在招聘单位（考公考编央国企）.md`，并维护累计台账 `数据/units.json`。

这一整套是**确定性脚本流程**：同样的输入必须得到同样的输出。不要在这里做网络请求，也不要手改清单——手改下一次就被覆盖。

## 执行顺序（不能颠倒）

```bash
cd "<工作区>"

python 脚本/build_list.py     # 1. 合并分片 → 判状态 → 校验并归位文件 → 写清单与 units.json → 存当日快照
python 脚本/sync_raw.py       # 2. 把归位后的路径/下载状态回写分片（可选，但建议）
python 脚本/verify.py         # 3. 自检，必须全绿
python 脚本/diff_report.py    # 4. 与上一个快照对比，看新增/状态变化
python 脚本/day_alert.py      # 5. 生成"今天截止/3 天内/明天开报"提醒文本
```

顺序理由：`sync_raw` 依赖 `build_list` 归位后的路径；`verify` 依赖前两步写完；`diff_report` 依赖当日快照；`day_alert` 依赖最新台账。

## 各步骤在做什么

### build_list.py

1. 按白名单 `SHARDS` 读分片（**不**用 `raw_*.json` 通配）
2. 与 `units.json` 合并，保留 `first_seen`
3. 按日期/时刻重算状态（见 `references/status-rules.md`）
4. 校验每个 `岗位表文件`：存在且 ≥10KB，否则改判 `失败`
5. **归位**：文件不在对应类别子目录的，自动 move 过去并把路径回写台账
6. 去重：丢旧条目、合并同日同子串项目
7. 写 `当前在招聘单位（考公考编央国企）.md`、`units.json`、`数据/历史/units_<日期>.json`
8. 清单带「首要提醒」「今日变化」两个自动生成的区块

### verify.py

校验四件事，任一不过就 `exit 1`：

- 统计数与分项一致（在招 + 未开始 + 已结束 + 待确认 = 总数）
- 每个 `已下载` 的文件真实存在且 >10KB
- 在招但无文件的单位都出现在清单第五节
- 同名同项目重复行（同名不同项目只是 INFO，属正常多批次）

### diff_report.py

对比最近两个 `数据/历史/units_*.json`，打印新增 / 消失 / 状态变化 / 新取得岗位表。
用于给用户的一句话汇报。

### day_alert.py

产出纯文本三段：`今天截止` / `N 天内截止` / `明天开报`。
今日截止会优先取 `报名截止` 里的 `HH:MM`，**已过的时刻不再报**（晚间跑时不会把 17:00 已关的算成还能报）。

## 常见故障

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 清单里出现两行同一单位 | 单位名被加了/减了括号后缀，去重键没命中 | 改分片里的 `单位` 字段统一写法，重跑 |
| `sync_raw.py` 报 `'list' object has no attribute 'get'` | 它读到了别的库的分片（结构不同） | 确认 `SHARDS` 白名单生效，别用通配 |
| 单位数暴涨几十上百 | 串库了，把外企/雄安条目并进来了 | 查 `SHARDS`；查是否有新分片被通配 |
| `verify` 报"文件缺失" | 文件名被改过，或文件被移到别处 | 让 `build_list` 的归位逻辑按 basename 兜底找 |
| 统计数与表格行数对不上 | 手改过清单 | 重跑 `build_list.py` |
| 已结束的条目又变回招聘中 | `报名截止` 只到日，而实际当天某时刻就关了 | 把时刻补进字段（`2026-11-04 08:00`） |

## 不要做的事

- **不要手改**清单 `md` 或 `units.json`——下一轮会被覆盖，且 `verify` 会报错
- **不要**为了让某个单位"看起来更新"而改它的 `项目` 名
- **不要**在 `build_list` 之前跑 `sync_raw`（路径还没归位）
- 台账 `units.json` 是累计的：某单位本轮没采到，它仍在台账里，`last_seen` 停在旧日期。这是设计，不是 bug

## 汇报

给用户 3~8 行：

- 总家数、在招数（附「已取得岗位表」数）
- 今日新增 / 状态变化
- 今天截止、3 天内截止（按 `day_alert` 的输出，别自己重算）
- 三个目录各多少文件、多少 MB
