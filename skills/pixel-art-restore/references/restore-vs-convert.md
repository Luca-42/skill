# 还原 vs 转换：两条路线的取舍

同一张源图（1536×1536 豆包生成的浅蓝黏菌角色，裁出主体 983×1175，背景粉 (250,204,211)）的实测数据，用于判断该走哪条路。

## 结论

**"还原"（ppa 识别原网格）> 任何"转换"（降采样 + 减色）。**
还原是"读取原有网格，一格取一色"，不丢信息；转换是"重新采样一次"，会丢细节并引入抽样噪点。

## 四路实测对比

| 路线 | 参数 | 输出 | 结果 |
|---|---|---|---|
| **ppa 还原** | `ppa src -o out --no-transparent` | 131×159 | 几乎忠实原图，1px 硬边无混色，眼睛高光/腮红/芯片走线/白斑全保 |
| 降采样 + 减色（"方法4"） | 128px / 29 色 | 128×153 | 能认出，但背景被顶成纯白、留成片黑散点 |
| 调色板量化（"方法6" Sweetie-16） | 128px / 16 色 / 无抖动 | 128×128 | 干净但色相变灰，细节丢 |
| 调色板量化（"方法6" PICO-8） | 128px / 16 色 / 抖动 0.2 | 128×128 | 失败，主体压成灰紫、整片噪点 |

## 转换路线为什么不行（给"必须转换"时参考）

### 分辨率阶梯

- 128px / 29 色：最佳；96px 次之；64px 五官碎掉；32px 报废
- 经验：**特征开始消失就加大分辨率**，而不是加分辨率救糊图

### 两个反直觉的失败点

1. **"对比度提高 20–30%"是硬乘 1.25**：浅粉背景 (250,204,211) 被顶成纯白（204×1.25=255），背景与主体的分离度反而变差。要用按直方图的自适应拉伸，不要硬乘系数。
2. **最近邻降采样会随机抽到描边黑像素**：软边图上抽样命中率不稳，128px 输出会带成片黑散点。而常见的"清理孤立像素"只查四邻域，清不掉成片散点。降采样前先做一次轻微高斯模糊可缓解。

### 调色板量化能不能用，取决于色域覆盖

- PICO-8 16 色里没有这种浅蓝 → 量化只能往黑/灰/粉撞，色相丢失；再叠加抖动，平涂区被点满噪点（抖动救不了色域不匹配）
- 换 Sweetie-16（柔和色调）+ 关抖动 → 立刻可用，但这是"碰巧配色域"，不是通用算法
- 判断方法：先看主体主色是否落在目标调色板附近，差得远就别量化，宁可还原后做轻度减色

## 什么时候真的该走转换

- 输入是照片/插画（`measure_grid.py` 判定"软边图像"且无像素画意图）
- 用户明确要"某套固定调色板风格"（PICO-8、Sweetie-16、NES 等），这时接受改色是需求本身
- 需要一次性抹掉细节做极低分辨率（32px 以下）的风格化图标

## 转换的最小可用参数（保底方案）

```
分辨率：主体长边 128px（特征复杂时 160）
量化：dominant 取色后减到 24–32 色，不做抖动
预处理：先轻度高斯模糊（半径 ≈ 原图格宽 1/3），避免抽样到孤立深色像素
后处理：整数倍最近邻放大预览，四邻域孤立点清理
```
