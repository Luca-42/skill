# 像素画还原（伪像素 → 真像素资产）

## 核心判断

**先还原，再改。** 对 AI 生成的伪像素图，直接从大图降采样等于重新采样一次，必然丢细节、引入抽样噪点；正确做法是识别原图自带的像素网格，一格取一个颜色。

但第一步必须先体检，因为 ppa 只会"缩小"，对已经是真分辨率的图会把它压烂（实测 131×159 的成品被压成 9×10，直接报废）。

## 工作流

### 1. 体检（决定要不要还原）

```bash
python scripts/measure_grid.py <图片>
```

看输出里的 `判定 / 动作`：

| 判定 | 含义 | 下一步 |
|---|---|---|
| 软边图像 | 生成模型的伪像素、或普通插画 | 是像素画意图 → 第 2 步；是照片 → 走转换，见 `references/restore-vs-convert.md` |
| 已经是 1px 真像素画 | 网格已是 1:1 | **不要跑 ppa**，直接去背或缩放 |
| 色块化像素画，疑似放大 N 倍 | 有平涂大色块 | `ppa -w N` 或最近邻缩小 N 倍 |
| 中间态 | 判据不足 | 直接跑 ppa 自动检测，看输出宽度是否符合预期 |

### 2. 还原

```bash
ppa <输入.png> -o <输出.png> --no-transparent
```

- 自动检测像素宽（源图 983 宽、格≈7.5px → 输出 131×159，属于正常）
- 检测不准（输出尺寸明显过小/过大）时才手填 `-w <像素格边长>`
- 需要指定目标像素宽（例如做 64px 角色）就直接给 `-w`，别事后非整数缩放

### 3. 去背（别用 ppa 自带的 `-t`）

`-t` 在软边源图上会产出粉灰交错的半透明噪点底，不可用。改用脚本：

```bash
python scripts/key_bg.py <还原.png> -o <抠图.png> --tol 42 --scale 8 --purge-bg
```

- 从边框洪水填充抠底 → 边缘干净、无半透明过渡
- 默认再跑两遍"边缘浅色残边清理"，清掉源图软边留下的浅色晕
- `--purge-bg` 清掉被主体围住的背景残留
- 默认裁掉四周透明留白；`--keep-specks` 保留散点；`--no-trim` 保留画布
- 输出 `<抠图>_x8.png` 的最近邻灰底预览，直接给人看

### 4. 验收清单

1. 输出尺寸是否是"源图宽 ÷ 检测格宽"，且接近整数
2. 放大 8 倍看：边缘是否只剩 1px 硬边、有没有混色/半透明过渡
3. 细节是否保住：眼睛高光、腮红、描边小结构、主体上的小色块
4. 轮廓外是否还有孤立散点（`key_bg` 已默认清一遍，仍残留就手擦）
5. 颜色数是否合理（不该出现上千种色，那是没量化干净）

### 5. 落地缩放

- 目标 64/96px：优先回炉 `ppa -w <格宽>` 让它自己检测到目标宽度；或从还原图做**整数倍**最近邻缩放
- 非整数比例（如 131→64 = 2.05）会产生宽窄不一的混合像素，一定要避免
- 上引擎前统一：转 sRGB、去半透明边缘、导出 PNG-8/PNG-24

### 批量

```bash
python scripts/batch_restore.py <输入文件夹> <输出文件夹> --scale 8
```

逐张跑 ppa + 去背 + 预览，失败的单张会打印原因并跳过。**注意**：批量前先抽样体检，混着真像素画会把它压烂。

## 常见坑

- **ppa 对 1px 图会过度缩小**：它假设输入被放大了，131×159 会变 9×10。跑前一定先 `measure_grid`。
- **`-t` 透明输出不可信**：粉灰噪点底，别直接用。
- **手填 `-w` 危害**：填错会让整图错位，只在自动检测明显失败时用。
- **palette 模式会改色**：`-c/--colors` 是量化到固定调色板，`--color-method dominant`（默认）才是保留原色。做还原用默认。
- **视频/GIF 输入**会自动走视频管线，逐帧检测网格，输出 `-f mp4|gif`；静态素材别用这条路径。
- **水印/文字**会干扰网格检测，先裁掉主体再做。

## 预处理（可选）

- 裁主体、去水印：按背景色算连通块，取最大连通区的外接框，裁出后交给 ppa
- 不要预先锐化或放大，会破坏网格周期
